| Blueprint component | Executable implementation | Limits / evidence still needed |
|---|---|---|
| Goals and authority (5.1, 9) | Owner API, authenticated separate authority process, versioned signed grants, expiry/revocation, budgets, parent/dependency records, exact action checking | Trusted notebook owner and host OS remain in the trusted computing base; no proof of inner alignment |
| Adapters and execution (5.2, 5.7) | Bounded filesystem, structured data, arithmetic, isolated Python, receipts and read-back checks | No external accounts, purchases, messages, unrestricted shell, browser automation or physical actions |
| Belief state (5.3) | Trainable GRU over typed history, elapsed/missing fields; structured observations separate from forecasts | Learned state is small and simulator-trained, not a general world representation |
| Evidence memory (5.4) | SQLite episodes, provenance and scope filtering, vector retrieval, claim support/contradiction/supersession, skill registry, explicit deletion and training consent | Retrieval similarity is not truth; pretrained text embeddings are not cross-modal grounding |
| World model (5.5) | Action-conditioned ensemble predicting outcome, state representation, changed/completion probability and delay; uncertainty; no-action examples | One-step forecasts; disagreement is an imperfect uncertainty proxy; live-tool transfer remains unvalidated |
| Planning and control (5.6, 6) | Replaceable LLM proposals, permissions filter, shallow beam ranking using trained world/policy scores, learned computation suggestions, stop/block handling | Horizon fixed at one; no claim of reliable long-horizon imagined rollouts; general plans/subgoals remain LLM-generated |
| Verification | Exact file/content/hash checks, actual arithmetic/data/code receipts, explicit UNKNOWN/BLOCKED states | Artifact existence/content is weaker than full semantic correctness; ordinary prose answers are marked ANSWERED_UNVERIFIED |
| Durable learning (7.1–7.4) | Actual gradient updates for recurrent encoder, ensemble heads, policy and controller; bounded resume, optimiser/checkpoint/data/source hashes; consented live replay candidate training and retention gates | Tiny curriculum; no demonstrated broad transfer, lifelong retention, or frontier reinforcement learning |
| Reasoning adaptation (7) | Real bounded QLoRA update/checkpoint code using mechanically checked synthetic targets | Awaiting hosted GPU execution; candidate remains disabled; tiny formatting/arithmetic validation cannot justify broad reasoning claims |
| Learning to learn (7.5) | Learned inspection/retrieval/action/stop choice on trial histories | Narrow computational strategy learning; not broad meta-learning; Titans-style neural memory is not implemented |
| Improvement (7.6, 14) | Failure clustering, isolated bounded planner-weight variants, evaluator process, archive, exact candidate inspection, owner promotion and rollback | Config search only; no arbitrary self-rewriting of production code, evaluator or authority; no ASI capability claim |
| Persistence (12) | Verified versioned Drive snapshots, SQLite online backups, checkpoint manifests, interrupted-copy fallback and resumable goals/training | Drive authorisation and a hosted session must occur in the user's account; abrupt termination can lose changes since last snapshot |
| Evaluation (10) | Family/time separated simulation diagnostics, random/frozen controls, calibration, rollout/retention checks, authority attacks; automatic hosted B0–B4 tool-agent tasks | Small public diagnostic tasks; not independent secret audits, competent-human comparisons or statistical evidence of general superiority |
| Broader perception (11 phase 4) | Text and structured observations, generic typed encoding; pretrained text retrieval in Colab | Screenshot/video/audio perception, learned multimodal fusion, robotics and physical simulators are not implemented |
| AGI/ASI (11 phases 5–7) | Research interfaces for measured extension | Neither achieved nor verified. Broad causal transfer, continual learning, research novelty and scalable independent evaluation remain open research problems |

Initial training is authorised by the notebook run and limited by configured steps. Later task training requires separate consent. Later model/planner promotion requires owner action and successful available gates; the model cannot rewrite those gates. An adaptation candidate's existence or a falling training loss is not presented as proof of better intelligence.

The local validation report distinguishes CPU executions from the actual hosted-Colab checks. Free Colab access, GPU type, network availability, Drive authorisation and installed kernel security features cannot be exercised from this development environment. If OS isolation is unavailable, generated Python execution is blocked with the specific reason; there is no unrestricted execution fallback.
